# aurum-member 云函数

`aurum-member` 是望潮微信小程序的年度会员、个人研究工作台和支付权益后端。当前唯一允许的新购买路线是免费云开发微信支付云调用：

`preparePurchase → cloudPay.unifiedOrder → wx.requestPayment → 支付通知/主动查单 → 事务内发放 365 天权益`

会员只有 `research-365d` 一个套餐，服务端固定价格 `128800` 分（1288 元/年），不自动续费。客户端只提交套餐 ID 和当前协议版本，不能提交或修改金额。

2026-07-29 云端核对确认只有两条旧虚拟支付订单，均为未付款且已关闭。历史记录继续保留并标记为 `legacy-virtual-archived`，但服务端已删除虚拟支付查单、发货、签名和 access_token 代码，不再需要 AppSecret、AppKey、OfferID 或道具 ID。任何非普通 JSAPI 的异常旧订单只会保守关闭或转人工核对，不会自动发放或回收权益。

## 支付可信边界

- 小程序通过 `wx.cloud.callFunction` 调用后端，用户身份直接取 `cloud.getWXContext().OPENID`，不再为新支付调用 `wx.login` 或 `code2session`。
- 云开发代管微信支付签名和证书；仓库、客户端和本函数都不需要商户 API 密钥、API V3 密钥或证书。
- 本地订单在统一下单前先写入数据库。只有微信主动查单返回的订单号、商户号、AppID、OpenID、套餐、金额、交易状态和交易号全部匹配，才在数据库事务内幂等发放权益。
- 支付通知入口要求不存在客户端 `OPENID`，且收到通知后仍会再次调用 `cloudPay.queryOrder`；客户端构造同名字段不能伪造支付成功。
- `wx.requestPayment` 的客户端成功回调只表示收银台流程结束，不直接发权益。
- 退款由运营方在微信支付商户平台人工按原路发起，不接入退款 API。普通查单进入 `REFUND` 时不能可靠证明本次退款金额，订单会转为 `fulfillment_review` 人工核对；金额未核实前不假定为全额退款，也不自动回收全部权益。

## 数据库集合

- `member_orders`
- `member_entitlements`
- `member_workspaces`

三个集合都保持“仅云函数可读写”。建议为 `member_orders` 建立两条组合索引：

- `openid` 升序、`status` 升序、`createdAt` 降序
- `openid` 升序、`createdAt` 降序

`member_entitlements` 与 `member_workspaces` 都以 OpenID 的 SHA-256 摘要作为文档 ID，不再在文档正文中冗余保存原始 OpenID。支付订单为完成微信查单验真、归属校验和退款复核仍保存必要的原始 OpenID，并按协议限定用途与保存期限。权益到期后，用户仍可查看、导出和删除自己的记录，但不能新增。

`member_workspaces` 嵌入字段包括：`watchItems`（含 `baselineFact` 历史快照）、`decisions`（含 `evidence`）、`inbox`（变化消息）、`reviewTasks`（节点待办）、`eventMarks`、台账与设置。变化分类见 `change-detect.js`，待办见 `review-tasks.js`。正式公开事实优先从同环境 `data_fact_latest` 盖章写入，客户端不能伪造服务端正式结论。

变化提醒只推送：结论变化、结论跨档、风险新增、触及用户失效条件；普通价格波动不进收件箱。

`eventMarks` 送达薄队列字段：`deliveryStatus`（pending/sent/failed/skipped）、`retryCount`、`lastError`、`nextRetryAt`、`notifiedAt`。每日 09:00（或对账 piggyback）补偿扫描失败项，最多重试 3 次。

可选环境变量 `WANGCHAO_SUBSCRIBE_EVENT_TMPL`：配置后才允许申请微信订阅消息；未配置时仅提供小程序内提醒，页面不得显示「微信提醒已开启」。

## 支付发布环境变量

普通 JSAPI 已固定为唯一新购路线，账号绑定与 JSAPI 授权已经确认，不再要求用环境变量重复声明支付方式或商户绑定状态。旧虚拟支付变量已从云函数环境删除。

| 变量 | 说明 |
| --- | --- |
| `WANGCHAO_PAYMENT_COMPLIANCE_APPROVED` | 主体、类目、业务范围和付费边界完成专业审查后才设为 `true` |
| `WANGCHAO_PAYMENT_RELEASE_APPROVED` | 协议、隐私、客服、真实付款/取消/回调/查单/退款和双端微信真机验收全部完成后才设为 `true` |
| `WANGCHAO_PAYMENT_TEST_MODE` | 仅受控真机验收期间设为 `true`；不等于正式发布 |
| `WANGCHAO_PAYMENT_TEST_OPENID_HASHES` | 允许验收的 OpenID SHA-256 编号，多个用逗号分隔；禁止填写原始 OpenID |
| `WANGCHAO_CLOUDPAY_SUB_MCH_ID` | 可选的公开商户标识覆盖值；不是密钥 |
| `WANGCHAO_CLOUD_ENV_ID` | 仅在平台没有注入 `TCB_ENV` 时使用的云环境 ID 备用值 |

正式购买采用“全部满足才开放”规则：已确认的商户/JSAPI 授权、人工原路退款流程、合规审查、交付验收缺一不可。API 退款不是本方案的前置条件，也不申请 `cloudPay.refund` 权限。不要为测试提前把正式交付开关写成 `true`。

为了避免“必须先真机付款验收、但验收前又不能打开正式开关”的循环，可在云函数后台登记受控账号的 64 位 OpenID SHA-256 验收编号。内部编号和测试开关不展示在普通会员页。仅在运营主体、合规审查和商户平台人工退款安排都完成后，才临时设置 `WANGCHAO_PAYMENT_TEST_MODE=true`。此时只有对应账号能真实付款，其他账号继续关闭；付款仍会真实扣除 1288 元，必须先确认付款账号和人工原路退款安排。验收结束立即关闭测试模式并清空名单，最后才设置正式发布开关。

历史虚拟支付已完成无密钥归档；不要重新添加 AppSecret、AppKey、OfferID、道具 ID 或虚拟支付环境变量。任何支付密钥都不得写入仓库、客户端、聊天或截图。

## 依赖安全处置

- 2026-07-28 使用 `npm audit --omit=dev` 再次复核生产依赖：通过 `overrides` 将传递依赖 `lodash.unset` 固定到已修复的 `4.18.0` 后，结果仍为 5 个高危、0 个中危、0 个严重；该覆盖已经过干净安装、CloudBase 数据库查询构造和原型污染烟雾测试。
- 剩余 5 个高危告警来自当前最新版官方 `wx-server-sdk@4.0.2` 固定使用的 CloudBase 传递依赖。业务代码不接受用户输入的请求 URL、代理、请求头或数据库字段路径，直接外呼只使用固定微信接口地址，以缩小已知告警的可达面。
- 不接受 npm 建议的破坏性降级：自动修复会把 `wx-server-sdk` 降到旧的 `2.5.3`，不符合当前云支付实现。也不在缺少兼容性证据时强行覆盖 `axios` 或 `lodash.set`；待官方 SDK 发布修复版本后优先升级并重新执行全套测试。
- 每次部署前继续运行 `npm audit --omit=dev`。若告警数量或等级上升，或出现可达的严重漏洞，停止发布并重新评估；当前书面处置不能替代后续升级。

## 订单恢复与退款

- `member-order-reconcile` 每 15 分钟启动一次全局订单扫描；待支付订单按 15 秒节流，已发放或待核对订单按 6 小时节流。
- 扫描使用持久游标并为 20 秒云函数超时预留收尾时间，不依赖用户再次进入会员页。
- 用户进入会员页或写入受保护工作台前也会复核订单；查单失败时保守降级为只读。
- 新购买是否开放与既有订单是否复核相互独立；即使正式购买关闭，已付款订单仍继续检查退款或异常状态。
- 两条历史虚拟支付订单均未付款并已关闭，只保留归档记录，不再访问上游接口。普通支付由运营方在商户平台人工原路退款；查单发现 `REFUND` 但金额未知时只进入人工核对，金额核实后再按全额或部分退款调整对应订单权益。退款通知仍可作为后续实时性增强，但不能替代退款金额验真。
- 购买记录和逐订单权益 credits 账本用于保证重复通知、重复查单和续期幂等；账本不一致时停止写入并标记人工核对。

## 发布门槛

1. 云开发商户绑定与 JSAPI 权限正常，商户平台人工原路退款流程可执行并留有可核验记录。
2. 正式运营主体全称、会员协议、隐私说明、公众平台隐私保护指引和微信客服完成。
3. 付费内容不交付具体买卖建议、收益预测或荐股；主体、类目和业务范围取得专业合规结论。
4. Android 微信与 iOS 微信内的小程序完成取消、真实付款、回调、主动查单、重复通知、重复查单，以及商户平台人工原路退款和权益核对验收。
5. `npm run check:payment`、`npm run audit`、`git diff --check` 和 `npm audit --omit=dev` 复核通过或对官方 SDK 告警形成书面处置结论。
6. 再依次区分开发版上传、微信审核、微信正式发布；任何一个都不能代替另一个。

自动续费未接入。微信当前的准入条件包含首次发布时长和近 30 天日均 DAU 达到 1 万，望潮首版只做单次购买固定 365 天权益。
