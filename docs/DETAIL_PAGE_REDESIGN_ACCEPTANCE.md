## 四、375px / 430px 多宽度说明（重要，如实说明方法局限）

验收要求覆盖 375px 与 430px 两个宽度。经核实，`miniprogram-automator` 自动化 SDK **不提供任何修改模拟器机型/视口宽度的接口**（已通读 SDK 的 `MiniProgram.js`、`Native.js`、`.d.ts` 源码确认，无 `setViewport`/`resize`/`device` 方法；`project.config.json`、`project.private.config.json` 均无相关配置项）。开发者工具当前唯一打开的模拟器机型为 iPhone 12/13 (Pro)，`screenWidth: 390`。

为不弄虚作假，采用了以下替代验证，而非声称做了真正的多宽度切换：
- 检查 `index.wxss` 中所有非 `rpx` 的像素级媒体查询，仅有两处：`@media (max-width: 340px)` 与 `@media (min-width: 700px)`，均不落在 375–430 区间内
- 检查 `index.js` 与 `index.wxml`，确认没有任何基于 `getSystemInfoSync`/`windowWidth`/`screenWidth` 的条件渲染逻辑
- 页面主体布局全部使用 `rpx`（微信规定的与设备宽度成比例的单位，750rpx 恒等于屏幕宽度的 100%），因此在没有上述两个断点、也没有 JS 宽度分支的前提下，375px、390px、430px 三个宽度的渲染结果在 CSS/JS 层面是等价的

因此本报告以 390px 模拟器截图代表 375px 与 430px 两档验收要求，但**这不等同于真正在两个不同宽度下各自截图**，特此说明，供后续如需要更严格证据时，可考虑改用支持视口切换的工具（如 Playwright 覆盖的 H5 预览，或未来版本的开发者工具）重新验证。
